## 1. 배경/문제
- 현재 `frontend` 프론트엔드 프로젝트는 **백엔드 API를 사용하지 않고**(로컬 상태/목업 등) 동작 중인 상태로 가정합니다.
- 목표는 `backend`에 **REST API**를 구현하고, 해당 API를 통해 **MySQL(tododb)** 에 데이터를 저장/조회/수정/삭제(CRUD)하는 구조로 전환하는 것입니다.

## 2. 목표
- **Backend**: Todo 도메인을 기준으로 CRUD REST API 제공 + MySQL 영속화
- **Frontend**: 기존 로컬 처리 로직을 API 호출 기반으로 변경
- **운영/개발**: 로컬 개발환경에서 `frontend ↔ backend ↔ mysql`이 함께 동작

## 3. 범위(스코프)
### 3.1 포함
- MySQL 접속 설정 및 JPA 연동
- Todo CRUD API
- DTO/Validation/예외 처리(표준 에러 응답)
- CORS 설정(프론트 개발 서버에서 백엔드 호출 허용)
- 프론트에서 API 연동(목록/등록/수정/삭제)

### 3.2 제외(초기 버전)
- 회원가입/로그인, 인증/인가(JWT 등)
- 배포(클라우드, 도커 컴포즈 등)
- 고급 검색/필터/정렬/페이징(필요 시 2차 확장)

## 4. 기술 스택(권장)
> 저장소에 실제 백엔드/프론트 코드가 아직 없는 상태이므로, 일반적인 교육용/실무형 구성을 기준으로 제안합니다.

- Backend: Spring Boot, Spring Web, Spring Data JPA, Validation
- DB: MySQL 8.x
- Frontend: 현재 프로젝트 스택(React/Vue/Vanilla 등)에 맞춰 `fetch/axios` 사용

## 6. 데이터 모델(초안)
### 6.1 테이블: `todos`
- `id` (PK, BIGINT, auto increment)
- `title` (VARCHAR, NOT NULL)
- `completed` (BOOLEAN, NOT NULL, default false)
- `created_at` (DATETIME)
- `updated_at` (DATETIME)

> `ddl-auto: update`를 사용하면 엔티티 기준으로 테이블이 자동 갱신됩니다(교육/로컬 개발용). 운영에서는 마이그레이션 도구(Flyway/Liquibase) 사용을 권장합니다.

## 7. API 설계(초안)
Base URL: `/api`

### 7.1 Todo
- **GET** `/api/todos`
  - 설명: Todo 목록 조회
  - 응답(예): `[{ id, title, completed, createdAt, updatedAt }, ...]`

- **POST** `/api/todos`
  - 설명: Todo 생성
  - 요청(예): `{ "title": "..." }`
  - 응답(예): `{ id, title, completed, createdAt, updatedAt }`

- **PUT** `/api/todos/{id}`
  - 설명: Todo 전체 수정
  - 요청(예): `{ "title": "...", "completed": true }`

- **PATCH** `/api/todos/{id}`
  - 설명: Todo 부분 수정(선택)

- **DELETE** `/api/todos/{id}`
  - 설명: Todo 삭제

### 7.2 에러 응답(권장 표준)
- 예: `{"timestamp":"...","status":400,"error":"Bad Request","message":"title is required","path":"/api/todos"}`

## 8. 백엔드 구현 상세(작업 항목)
### 8.1 프로젝트 생성
- `backend` Spring Boot 프로젝트 생성
- 의존성 추가
  - spring-boot-starter-web
  - spring-boot-starter-data-jpa
  - mysql-connector-j
  - spring-boot-starter-validation

### 8.2 설정
- `application.yml`에 datasource/jpa 설정 적용
- 로컬 포트 예: `server.port: 8080`

### 8.3 도메인 계층
- `Todo` 엔티티
- `TodoRepository extends JpaRepository<Todo, Long>`
- Service 계층(트랜잭션, 비즈니스 로직)

### 8.4 API 계층
- Controller (`/api/todos`)
- DTO 분리
  - CreateTodoRequest(title)
  - UpdateTodoRequest(title, completed)
  - TodoResponse
- Validation
  - title: `@NotBlank`, 길이 제한 등

### 8.5 예외/검증 처리
- NotFound(없는 id) → 404
- Validation 실패 → 400
- 공통 예외 처리: `@RestControllerAdvice`

### 8.6 CORS
- 프론트 개발 서버(origin)에서 접근 가능하도록 허용
  - 예: `http://localhost:3000` 또는 `http://localhost:5173`
- 허용 메서드: GET/POST/PUT/PATCH/DELETE

## 9. 프론트엔드 연동 상세(작업 항목)
> 현재 저장소에 `frontend`가 없으므로, 기존 프로젝트 구조에 맞게 아래 항목을 적용합니다.

- API Base URL 환경변수화
  - 예: `VITE_API_BASE_URL=http://localhost:8080` 또는 `REACT_APP_API_BASE_URL=...`
- 기존 로컬 상태 처리 로직을 API 호출로 교체
  - 목록 로딩: GET `/api/todos`
  - 등록: POST `/api/todos`
  - 체크/수정: PUT/PATCH `/api/todos/{id}`
  - 삭제: DELETE `/api/todos/{id}`
- 네트워크 오류/로딩 상태 UI 추가(최소)
